Intro

2편에서 WebFlux의 동작 방식과 Non-blocking 아키텍처를 살펴봤다. 이번 편에서는 실제 개발의 첫 단계인 데이터베이스 구성과 JWT 기반 인증 구현을 다룬다.

단순히 테이블을 만들고 로그인을 구현하는 것처럼 보이지만, WebFlux 환경에서는 MVC와 다르게 고려해야 할 부분들이 있다. Flyway로 마이그레이션을 관리하는 방법, Spring Security를 WebFlux에 맞게 설정하는 방법, 그리고 Refresh Token을 안전하게 다루는 방법을 코드와 함께 정리한다.

ERD 설계

users
ㄴid (PK)
ㄴusername (UNIQUE)
ㄴpassword (BCrypt)
ㄴrole (USER / ADMIN)
ㄴcreated_at
ㄴ updated_at

coupons
ㄴid (PK)
ㄴname
ㄴtype (PERCENT / FIXED / FREE)
ㄴdiscount_value
ㄴtotal_stock
ㄴremaining_stock
ㄴcreated_at
ㄴ updated_at

coupon_issues
ㄴid (PK)
ㄴcoupon_id (FK → coupons)
ㄴuser_id (FK → users)
ㄴissued_at
ㄴcreated_at
ㄴ updated_at

coupon_issues에 UNIQUE(coupon_id, user_id) 제약을 걸었다. Redis Lua 스크립트에서 1차로 막고, DB에서 2차로 막는 이중 방어 구조다.

Flyway로 마이그레이션 관리

DB 스키마를 코드로 관리하기 위해 Flyway를 사용했다. resources/db/migration/ 경로에 SQL 파일을 버전 순서대로 관리한다.

resources/
ㄴ db/
    ㄴ migration/
        ㄴV1__init.sql        # 테이블 생성
        ㄴ V2__init_data.sql   # 초기 데이터 (admin 계정, 쿠폰)

Flyway는 기본적으로 Spring Boot가 자동 실행하지만, WebFlux 환경에서는 R2DBC가 기본 DataSource라 Flyway가 JDBC DataSource를 찾지 못하는 문제가 생긴다. 이를 해결하기 위해 Flyway를 직접 Bean으로 등록했다.

@Configuration
public class FlywayConfig {

    @Bean(initMethod = "migrate")
    public Flyway flyway(FlywayProperties flywayProperties) {
        return Flyway.configure()
                .dataSource(
                        flywayProperties.url(),
                        flywayProperties.user(),
                        flywayProperties.password()
                )
                .locations(flywayProperties.locations().toArray(String[]::new))
                .baselineOnMigrate(true)
                .load();
    }
}

application.yml에서 Flyway 자동 실행을 끄고 직접 관리한다.

spring:
  flyway:
    enabled: false
    url: jdbc:mysql://localhost:3306/load_testing
    user: root
    password: password
    locations: classpath:db/migration

JWT 인증 구조

JWT는 Access Token과 Refresh Token 두 가지로 구성했다.

Access Token

  • 만료 시간: 1시간
  • 저장 위치: 응답 바디 → 클라이언트 메모리
  • 역할: API 요청 인증

Refresh Token

  • 만료 시간: 7일
  • 저장 위치: HttpOnly Cookie
  • 역할: Access Token 재발급

Access Token을 메모리에 저장하는 이유는 localStorage에 저장하면 XSS 공격으로 탈취될 수 있기 때문이다. 메모리에 저장하면 페이지를 새로고침하면 사라지지만, Refresh Token으로 자동 재발급하면 된다.

Refresh Token을 HttpOnly Cookie에 저장하는 이유도 동일하다. JavaScript로 접근 자체가 불가능하기 때문에 XSS 공격으로부터 안전하다.

Refresh Token Rotation

Refresh Token을 재사용하면 탈취 시 장기간 악용될 수 있다. 이를 방지하기 위해 Refresh Token Rotation을 적용했다. 재발급 시 새로운 Refresh Token을 발급하고 기존 토큰을 무효화한다.

public Mono<TokenResult> reissue(String refreshToken) {
    try {
        jwtProvider.validateToken(refreshToken);
    } catch (BusinessException e) {
        if (e.getErrorCode() == ErrorCode.TOKEN_EXPIRED) {
            return Mono.error(new BusinessException(ErrorCode.REFRESH_TOKEN_EXPIRED));
        }
        return Mono.error(e);
    }

    Long userId = jwtProvider.getUserId(refreshToken);

    return reactiveRedisTemplate.opsForValue()
            .get("refresh:" + userId)
            .switchIfEmpty(Mono.error(new BusinessException(ErrorCode.TOKEN_INVALID)))
            .flatMap(savedToken -> {
                // Redis에 저장된 토큰과 요청 토큰 비교 → 탈취 감지
                if (!savedToken.equals(refreshToken)) {
                    return reactiveRedisTemplate.opsForValue()
                            .delete("refresh:" + userId)
                            .then(Mono.error(new BusinessException(ErrorCode.TOKEN_INVALID)));
                }

                String newAccessToken = jwtProvider.generateAccessToken(userId);
                String newRefreshToken = jwtProvider.generateRefreshToken(userId);

                return reactiveRedisTemplate.opsForValue()
                        .set("refresh:" + userId, newRefreshToken,
                                Duration.ofMillis(jwtProperties.refreshTokenExpiration()))
                        .thenReturn(new TokenResult(newAccessToken, newRefreshToken));
            });
}

Redis에 저장된 토큰과 요청으로 온 토큰이 다르면 탈취된 것으로 판단하고 즉시 무효화한다.

로그아웃 처리

Access Token은 만료되기 전까지 유효하기 때문에 단순히 Redis에서 Refresh Token을 삭제하는 것만으로는 부족하다. Access Token을 블랙리스트에 등록해 만료 전에도 차단해야 한다.

public Mono<Void> logout(Long userId, String accessToken) {
    // 남은 만료 시간만큼만 블랙리스트에 저장 → Redis 메모리 낭비 방지
    long expiration = jwtProvider.getClaims(accessToken)
            .getExpiration()
            .getTime() - System.currentTimeMillis();

    return tokenBlacklistService.addBlacklist(accessToken, Duration.ofMillis(expiration))
            .then(reactiveRedisTemplate.opsForValue()
                    .delete("refresh:" + userId)
                    .then());
}

Spring Security WebFlux 설정

MVC의 HttpSecurity 대신 WebFlux에서는 ServerHttpSecurity를 사용한다.

@Configuration
@EnableWebFluxSecurity
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthenticationFilter;

    @Bean
    public SecurityWebFilterChain securityWebFilterChain(ServerHttpSecurity http) {
        return http
                .csrf(ServerHttpSecurity.CsrfSpec::disable)
                .formLogin(ServerHttpSecurity.FormLoginSpec::disable)
                .httpBasic(ServerHttpSecurity.HttpBasicSpec::disable)
                // JWT Stateless → 세션 저장 안 함
                .securityContextRepository(NoOpServerSecurityContextRepository.getInstance())
                .authorizeExchange(exchanges -> exchanges
                        .pathMatchers("/api/auth/**").permitAll()
                        .anyExchange().authenticated()
                )
                .addFilterAt(jwtAuthenticationFilter, SecurityWebFiltersOrder.AUTHENTICATION)
                .build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

JWT 필터는 WebFilter를 구현해서 모든 요청에서 토큰을 검증하고 인증 정보를 ReactiveSecurityContextHolder에 저장한다.

@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter implements WebFilter {

    private final JwtProvider jwtProvider;
    private final TokenBlacklistService tokenBlacklistService;

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, WebFilterChain chain) {
        String token = extractToken(exchange.getRequest());

        if (token == null) {
            return chain.filter(exchange);
        }

        return tokenBlacklistService.isBlacklisted(token)
                .flatMap(isBlacklisted -> {
                    if (isBlacklisted) {
                        return chain.filter(exchange);
                    }

                    try {
                        jwtProvider.validateToken(token);
                        Long userId = jwtProvider.getUserId(token);

                        Authentication auth = new UsernamePasswordAuthenticationToken(
                                userId, null, List.of()
                        );

                        return chain.filter(exchange)
                                .contextWrite(ReactiveSecurityContextHolder
                                        .withAuthentication(auth));
                    } catch (BusinessException e) {
                        return chain.filter(exchange);
                    }
                });
    }

    private String extractToken(ServerHttpRequest request) {
        String bearer = request.getHeaders().getFirst(HttpHeaders.AUTHORIZATION);
        if (bearer != null && bearer.startsWith("Bearer ")) {
            return bearer.substring(7);
        }
        return null;
    }
}

DataInitializer

테스트 시 매번 수동으로 Redis와 DB를 초기화하는 게 번거롭기 때문에 서버 재시작 시 자동으로 초기화하는 DataInitializer를 만들었다.

@Component
@RequiredArgsConstructor
public class DataInitializer implements ApplicationRunner {

    private final CouponRepository couponRepository;
    private final CouponIssueRepository couponIssueRepository;
    private final UserRepository userRepository;
    private final ReactiveRedisTemplate<String, String> reactiveRedisTemplate;
    private final AppProperties appProperties;

    @Override
    public void run(ApplicationArguments args) {
        if (!appProperties.dataInit().enabled()) {
            log.info("데이터 초기화 스킵");
            return;
        }

        // coupon_issues 초기화
        couponIssueRepository.deleteAll().subscribe();

        // Redis refresh 토큰 초기화
        userRepository.findAll()
                .flatMap(user -> reactiveRedisTemplate
                        .delete("refresh:" + user.getId()))
                .subscribe();

        // 쿠폰 Redis 재고 초기화
        couponRepository.findAll()
                .flatMap(coupon -> reactiveRedisTemplate.opsForValue()
                        .set("{coupon:" + coupon.getId() + "}:stock",
                                String.valueOf(coupon.getTotalStock()))
                        .then(reactiveRedisTemplate
                                .delete("{coupon:" + coupon.getId() + "}:users"))
                        .doOnSuccess(r -> log.info("쿠폰 {} Redis 초기화 완료",
                                coupon.getId())))
                .subscribe();
    }
}

application.yml에서 활성화 여부를 제어한다.

app:
  data-init:
    enabled: false  # 초기화 필요할 때만 true
